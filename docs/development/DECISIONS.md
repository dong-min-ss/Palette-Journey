# 결정 기록

## 팔레트의 보상 범위

기본 색과 지역 모의 방문 보상을 제공한다. 개인 색을 새로 구매하거나 해금하는 기능을 제거하고, 기존 작품에 사용한 저장 색은 계속 읽을 수 있게 한다.

## 지역 그림일기 미션

차량 디버그 에뮬레이터의 개발 도구에서 지역과 연령대를 직접 고른다. 미취학을 초기값으로 제공하며, 지역 또는 연령대를 변경하면 생성 결과를 지워 이전 선택의 미션이 남지 않게 한다. 지역·연령 조합별로 준비한 사진·관찰·그림 미션을 앱 안에서 보여준다. 글레오 음성 호출은 별도 검증 범위다.

## 2026-11-06 — 선택 색의 조명 API 연동

- 검증한 Vehicle SDK2.3.2를 본앱에 추가한다. 실제 LED 검증 전 DEBUG 에뮬레이터·정차·명시적 폰 opt-in·차량 전용 화면 foreground에서만 제어한다. 다른 화면을 위한 백그라운드 서비스는 만들지 않는다.
- 서버 세션별 메모리 요청과 10초 만료를 사용한다. 색ID는 실제 보유 팔레트로 해석하고 RGB를 재매핑하지 않는다. 적용 직전 최신 요청·가족·P/속도 신호를 재검사한다. 같은 색은 다시 쓰지 않는다.
- SDK setter 응답만으로 성공 처리하지 않고 독립 get의 정확한 HEX 일치를 보고한다. 가족 인증 ACK이며 하드웨어 서명 증명은 아니다. 끄기·화면 이탈·통신 단절은 새 적용을 중단하고 마지막 색을 유지한다. 밝기나 원래 색 자동 복원은 범위 밖이다.

## 2026-11-05 — 폰 녹음의 차량 재생 길이

MediaRecorder가 만든 WebM은 네이티브 MediaPlayer에서 재생되더라도 전체 길이가0일 수 있다. 정상 네이티브 길이를 우선 사용하고, 없으면 서버에 저장한 녹음 시간을 전체 길이·탐색 범위·완료 표시에 사용한다. 사용자 원음을 다른 음성으로 재합성하거나 교체하지 않는다.

## 2026-11-05 — Android 폰 보조 앱과 한 기기 작성

- 사용자 요청에 따라 아이폰 로컬 HTTPS 인증서 준비를 중단하고 Android 폰 에뮬레이터 시연용 `:companion`을 추가한다. 차량용 `:app`과 별도 패키지·APK이며 기존 화면과 서버를 재사용하는 WebView 방식이다. 새 런타임/플러그인 의존성은 추가하지 않는다.
- 기본 흐름은 폰에서 그림 → 현재 페이지에 녹음 → 명시적 저장 → 차량에서 감상이다. 준비된 질문은 보호자가 읽거나 자유롭게 이야기하는 참고 문구이며 생성형 글레오 대화로 표현하지 않는다. 기존 차량 녹음/업로드는 선택 경로로 보존한다.
- 시연 서버는 PC에 유지하고 adb reverse로 앱의 localhost:3000에 연결한다. 이 주소만 탐색/마이크 접근을 허용하고 RECORD_AUDIO 런타임 권한과 MODIFY_AUDIO_SETTINGS 일반 권한을 적용한다. 인증서 신뢰 설치·HTTP 보안 컨텍스트 강제 허용·JavaScript 네이티브 브리지는 사용하지 않는다.
- 녹음 전에 그림 저장이 완료되어야 하며 실패/취소 시 마이크를 열지 않는다. 녹음은 현재 페이지에만 연결하고 충돌 시 덮어쓰지 않는다. 앱 이탈 시 일시정지하고 자동 재개하지 않는다. 서버 저장 전 RAM 녹음은 앱 종료 시 유실될 수 있다.
- Android 보조 앱은 파일 내려받기 버튼을 숨기고 저장 재시도를 제공한다. 웹 브라우저의 기존 파일 내려받기는 유지한다. 여행책은 페이지 추가·기록 불러오기·재방문 설정을 별도 여백과 구분선으로 배치한다.
- API37 Google Play x86_64 폰 AVD는 영문 임시 경로 `%TEMP%/PaletteJourneyPhone`와 소프트웨어 GPU로 구성한다. 기존 차량 AVD·가족 기록은 초기화하지 않는다. APK는 개발용 자동 서명이며 PC 서버가 필요한 MVP 시연 산출물로 제공한다.

## 2026-11-01 글레오 AI 대화 일기

- 핵심 타깃을 글쓰기가 아직 어려운 미취학 아동·초등 저학년으로 명확히 한다. 글 입력은 선택 사항이다.
- 녹음은 독백 대신 오늘 경험에 관한 글레오 AI의 짧은 질문과 아이 답변이 오가는 대화 전체를 저장하는 방식이다. 보호자 시작·비공개 보관·재생·삭제와 아이의 건너뛰기·일시정지·종료를 기획한다.
- 실제 음성/대화/녹음 API 지원과 이용 조건은 확인 전이며 구현 완료로 표시하지 않는다. 기존 색 수집·지역 스티커·재방문·앰비언트 조명 기획은 유지한다.

## 2026-10-31 지역 스티커와 재방문 기반 규칙

- 지역 스티커는 방문 업적이자 일기 표현 도구다. 지급 조건을 임의 확정하지 않고 검증된 방문 이후의 보유·배치 규칙부터 구현한다.
- 폭과 높이를 독립 저장하고 같은 보유 자산을 여러 인스턴스로 사용한다. 기존 단일 작품의 DB/HTTP 형식은 유지한다.
- 재방문 안내는 같은 가족/자녀의 이전 여행 일기 중 최근 기록을 선택한다. 한국 날짜 기준 당일 기록은 제외하고 전달 이력으로 같은 방문의 반복 안내를 막는다. 실제 재알림 간격과 지역 반경은 미정이다.
- 현재 코드는 순수 도메인 함수이며 클라이언트가 방문을 증명하거나 알림을 발송하지 않는다. DB·권한·위치 이벤트·UI 연결은 별도 구현한다.

## 2026-10-31 여행 그림일기 개정

- 사용자 요청에 따라 어린 자녀를 핵심 타깃으로 확정하고 컬러링을 스티커·그림·글·음성을 담는 여행 그림일기로 확장한다.
- 여행 후 자동 도안은 제외하고 사전 제작 도안/스티커와 이미 작성한 페이지의 여행책 구성을 사용한다.
- 실제 경로 통과·유효 체류·지정 장소 방문으로 색을 수집한다. 특산품·음식·문화까지 전국 색깔 사전을 확장한다. 수집은 콘텐츠 ID 기준이며 동일 HEX가 지역 의미를 지우지 않도록 한다.
- 주제형 챌린지의 랭킹 기준은 유효 좋아요다. 보호자 승인과 가족 비공개 기본값을 적용하고 음성 공개는 별도 선택한다.
- 기존 기본색·티켓·컬러링 코드는 재사용한다. 현 단일 작품 저장 구조는 여러 자녀/일기/페이지를 지원하지 않으므로 후속 스키마 설계가 필요하다. 이번에는 문서만 변경한다.

- 코드와 토큰은 해시로 저장하고, 세션 종료/만료를 모든 참여자 접근 시 검사한다. 상태는 SQLite에 영속 저장한다.

## 2026-11-02 — 그림일기에 대화 통합 및 단일 파일 재생으로 수정
- 사용자는 음성을 별도 콘텐츠가 아니라 완성된 날짜별 그림일기에 붙은 대화 기록으로 정의했다. 음성 일기 탭/답변만 듣기를 없애고 그림 아래 재생 버튼 하나와 접힌 기록 관리로 통합한다. entryDate를 페이지 데이터에 보존하고 기존 데이터는 일기 생성일의 한국 날짜로 표시한다. 구형 Android 클라이언트 저장도 날짜를 지우지 않는다.

- 질문 RMS에 답변 RMS를 맞추되 질문 gain은 최대0.35로 낮춘다. 답변 원음 자체는 변조하지 않는다. 파생 WAV는 원본 revision에 묶고 생성 중 삭제/만료에도 권한과 revision을 재검사하여 되살리지 않는다. 실제 차량 질문 원음을 저장하는 문제와 현재 재합성 재생 파일은 계속 구분한다.

## 2026-11-02 — 모의 경주 방문 판정과 보상 출처

## 2026-11-05 — 차량 홈과 가족 연결 첫 사용 개선
- 차량 홈의 각 기능은 설명을 포함한 단일 버튼으로 제공한다. 넓은 화면은 2열, 좁은 화면은 1열로 표시한다.
- 연결이 확인되지 않았을 때 가족 연결 시작을 먼저 제공한다. QR 발급은 활성 가족 연결, 페이지 공유는 선택할 수 있는 페이지가 있는 경우에 활성화한다.
- 녹음 전에는 동의와 시작 방법을 보여주고, 현재 질문은 대화가 진행 중일 때 표시한다. 녹음·보관 안내와 음성 설정은 접어서 아래에 배치한다.
- 차량 홈과 하위 화면은 웹 스케치북의 아이보리 배경과 종이색 카드를 사용한다. 모래색 제목 영역과 갈색 강조색을 적용하고, 활성·포커스·비활성 상태는 밝은 배경에서 구분한다. 차량 사전 WebView에도 같은 색을 사용한다.
- 가족 연결의 자동 조회는 버튼을 잠그지 않는다. 명시적 QR 발급·가족 변경만 중복 클릭을 잠그며, 이전 자동 조회 응답은 명시적 작업 이후 화면에 적용하지 않는다.

## 2026-11-13 — 공모전 제출용 release

- `paletteSubmissionDemo=true`를 명시한 release만 `EMULATOR_DEMO=true`로 빌드한다. 기존 debug 시연은 유지하며 일반 release의 실차 조작 잠금과 HTTP 차단은 유지한다. 시연 권한은 release/debug 여부와 분리하되 모든 차량 시연 화면은 기존 ranchu/goldfish 하드웨어 확인을 함께 요구한다.
- 제출 release는 `debuggable=false`이고 별도 로컬 RSA 키로 서명한다. 키와 비밀번호는 `android/.signing/`에 보관하고 Git에서 제외한다. 차량·폰에 `.submission` 패키지 접미사를 사용해 기존 앱의 가족·그림·음성과 서명 충돌을 피한다. 기존 기록을 자동 이관하지 않는다.
- 제출 차량만 `10.0.2.2` HTTP를 허용한다. 다른 HTTP 호스트는 차단한다. 모의 주행 화면만 submission Manifest에서 distractionOptimized로 설정해 콘솔 D 상태에서도 모의 거리 갱신을 계속한다. 이 화면은 에뮬레이터 밖에서 잠긴다.
- 제출 차량 release에서는 부분 R8 최적화를 끈다. 초기 빌드에서 Kotlin/AndroidX 초기화 IllegalAccessError와 release 테스트의 tracing 클래스 누락이 재현됐다. 디버깅 허용과 최적화 여부는 별개이며 서명된 비디버그 release 특성은 유지한다.
- APK 파일명에 사용자 확인한 개인 참가자명 박동민을 반영한다. README에 AVD 설정과 실제 조회한 화면 규격, 서버·ADB·권한 설정을 명시한다.

## 2026-11-15 — Windows 연속 주행 검증 실행 조건

- 에뮬레이터 자체 종료와 앱 예외를 구분하도록 Windows 이벤트 로그·프로세스 종료 코드·기기 단계 로그를 함께 확인한다. SwiftShader에서 네이티브 접근 위반을 재현했고 host GPU 조건으로 전환해 전체 흐름을2회 연속 완료했다. 이 PC의 검증용 명령은 host GPU/Vulkan 비활성/단독 AVD/호스트 오디오 비활성으로 정리한다. 일반 실차 설정이나 음성 청취 품질로 확대 해석하지 않는다.
- 연속 주행 검증은 실제 Console→CarPropertyManager SDK 신호 경로를 유지하고, 서버·가족만 인메모리로 격리한다. 300m/정차5초/도시별3색2스티커 정책은 완화하지 않는다. 운영 앱/API/APK를 수정할 근거는 이번 성공/실패 기록에서 확인되지 않아 제출 APK를 그대로 유지한다.
- 테스트는 고유 실행 ID, 제한 시간과 실제 DOM 상태, 재생성된 활성 화면 확인, 완료 단계 및 JUnit 성공을 모두 만족해야 통과한다. 검증 결과와 실행 환경을 저장소 문서에 명시한다.
